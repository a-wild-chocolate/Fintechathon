               1.    How to kick start 
                  
                 On a Windows operating system, an SSH client such as for PuTTY (http://www.putty.org) can 
                 be downloaded. A Mac OS X user can use the Terminal application from the Finder, or under 
                 Application/Utilities/Terminal.app.  
                 When using the SSH connection, the cluster’s address must be added. When the connection is 
                 made, a username and password must be entered at the prompt. 
                 Optionally, after logging in, the password used can be changed using the passwd command: 
                 $ passwd 
                  
               2.    Overview of scheduler commands (SLURM) 
               srun – submit interactive task  
                
               sbatch – submit batch script to SLURM 
                
               srun and sbatch important flags to remember: 
                
                     ‐p   ‐ partition to use.  Please use “‐p partition name” for all your tasks to GPU compute 
               nodes.  Partition name: NA100q, PA100q, PA400q, RTXA6Kq, DGxq… 
                    ‐n   ‐ number of tasks to execute. Optional. By default, 1 task. 
                    ‐c    ‐ cores to allocate per each task. For hyper‐threaded tasks. Optional. By default, 1 core 
               per task. 
                    ‐N ‐ number of servers to allocate. Optional. By default, number of servers will be selected 
               by scheduler. 
                    ‐‐gres=gpu:1 or ‐‐gres=gpu:2 ‐ number of GPUs to allocate for the job. Must be used if your 
               job is using GPU 
                
               sinfo ‐ view information about Slurm nodes and partitions 
                
               Example: 
               $ sinfo 
                
               squeue – show current tasks in queue 
                
               Example: 
               $ squeue 
                 
               sacct – show previous jobs 
                
               Example:  
               $ sacct 
                                                                                                              2 
                
                
               scancel ‐ Kill a job 
                
               Example: 
               $ scancel xx         (xx=job id) 
                
               scontrol – show job details 
               Example: 
               $ scontrol show job xx        (xx=job id) 
                
                
               3.    Loading and Unloading Modules 
                
               3.1 Cluster environment has certain modules pre‐compiled and ready to be used – different 
               versions of Cuda toolkit, MPI, different compilers and so on. 
               Use the following command to list the default modules added to user environment (.bashrc file 
               in user home folder): 
                
               $ module list 
                
               3.2 To see all available modules type 
                
               $ module avail 
                
               In the list there are two kinds of modules: • local modules, which are specific to the node, or 
               head node only • shared modules, which are made available from a shared storage, and which 
               only become available for loading after the shared module is loaded. 
                
               3.3 Modules can be loaded using the add or load options. A list of modules can be added by 
               spacing them: 
                
               $ module add cuda11.1/toolkit/xxxx 
                
               By loading a certain module – system will add certain variables to your environment and modify 
               your PATH/ LD_LIBRARY_PATH variables. 
                
               To add module to your environment permanently – modify your .bashrc file accordingly.

                 4.     srun 
                 srun is suitable for a simple task and for tasks that don’t take long to complete ‐ for which you 
                 would like to receive an output to your SSH terminal. 
                  
                 4.1 Simple job with srun 
                  
                 Simplest srun command be: 
                 $ srun ‐p Partition name ‐n 1 abc.out  (you can use command “sinfo” to list the Partition name) 
                  
                 e.g. $ srun ‐p NA100q ‐n 1 abc.out 
                  
                 For instance: 
                 e.g. $ srun ‐p NA100q ‐n 1 hostname 
                 srun: Job step created 
                 node01 
                  
                 4.2 srun job with GPU

                 other running jobs by sharing the GPU:

       4.3 srun job with several cores and several GPUs 
        
       For each 4 cores that you use (either 4 tasks with single core or single task with 4 cores) 
       please use 1 GPU. Try to stick to this allocation blocks:  4 cores and 1 GPU. For instance if you 
       plan to use 8 cores and not sure how many GPUs you need – 1/2/3/4, use 2: 
        
       Please note that “nbody” here is not MPI binary and it is mentioned here only as srun example. 
       For such non‐mpi task normally it does not make sense to use more than “‐n 1” since all these 
       executions will be completely separate, unaware of each other: 
        
       $ srun –p partition name ‐n 8 ‐c 1 ‐‐gres=gpu:2 
       /cm/shared/apps/cuda11.1/sdk/current/7_CUDALibraries/simpleCUBLAS/simpleCUBLAS 
        
       5. sbatch 
        
       5.1 Simple job with sbatch 
        
       Create the following file (testjob.sh): 
        
       #!/bin/sh 
        
       #SBATCH ‐p partition name 
       If you want to use dedicate node, add in (#SBATCH ‐w nodelist) 
       #SBATCH ‐n 1 
        
       hostname 
        
                                                 5 
        
       Submit the job with sbatch. Output will be in slurm‐<JOBID>.out: 
        
       $ sbatch testjob.sh 
       Submitted batch job xxx 
       $ cat slurm‐xxx.out 
       Hostname (e.g. node01)

       5.3 sbatch job with several cores and GPUs 
        
       Create the following file: 
        
       #!/bin/sh 
        
       #SBATCH ‐p gpu 
       #SBATCH ‐‐gres=gpu:1 
       #SBATCH ‐n 4 
                                                 6 
        
                 
                module load cuda11.1/toolkit 
                 
                srun /path/to/your/program 
                 
                 
                Submit the job with sbatch.  This will run will 4 instances of your program, all of them will utilize 
                1 GPU. The same job can be run interactively (output is directed to your SSH terminal instead of 
                slurm‐<JOBID>.out file)  with the following srun command line: 
                 
                $ srun ‐p gpu ‐n 4 ‐‐gres=gpu:1 /path/to/your/program

              7.    MPI Examples 
              7.1 OpenMPI sbatch job 
               
              Sample MPI program (helloworld.c): 
               
              /* test of MPI */ 
              #include "mpi.h" 
              #include <stdio.h> 
              #include <string.h> 
               
              int main(int argc, char **argv) 
              { 
              char idstr[2232]; char buff[22128]; 
              char processor_name[MPI_MAX_PROCESSOR_NAME]; 
              int numprocs; int myid; int i; int namelen; 
              MPI_Status stat; 
               
              MPI_Init(&argc,&argv); 
              MPI_Comm_size(MPI_COMM_WORLD,&numprocs); 
              MPI_Comm_rank(MPI_COMM_WORLD,&myid); 
              MPI_Get_processor_name(processor_name, &namelen); 
               
              if(myid == 0) 
              { 
                printf("WE have %d processors\n", numprocs); 
                for(i=1;i<numprocs;i++) 
                { 
                  sprintf(buff, "Hello %d", i); 
                                                                                                        8 
               
            MPI_Send(buff, 128, MPI_CHAR, i, 0, MPI_COMM_WORLD); } 
            for(i=1;i<numprocs;i++) 
            { 
              MPI_Recv(buff, 128, MPI_CHAR, i, 0, MPI_COMM_WORLD, &stat); 
              printf("%s\n", buff); 
            } 
        } 
        else 
        { 
          MPI_Recv(buff, 128, MPI_CHAR, 0, 0, MPI_COMM_WORLD, &stat); 
          sprintf(idstr, " Processor %d at node %s ", myid, processor_name); 
          strcat(buff, idstr); 
          strcat(buff, "reporting for duty\n"); 
          MPI_Send(buff, 128, MPI_CHAR, 0, 0, MPI_COMM_WORLD); 
        } 
        MPI_Finalize(); 
        }
